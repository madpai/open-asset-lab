# Mobile AI performance

**VERIFIED current cost warning:** MegaMod supports Android and its existing `nav.c`/`brain.c` already have host bot work. [Godot's navigation performance guide](https://docs.godotengine.org/en/4.2/tutorials/navigation/navigation_optimizing_performance.html) warns that parsing complex render geometry and runtime nav baking can stall frames; simple collision input and offline baking reduce cost. The installed Natural Selection 2 bot motion code marks full path calls expensive and caches paths. These support budgeting, not a universal tick rate.

**Proposed schedule:** movement/collision may update every simulation tick; perception and strategic choice should use separate lower frequency, deterministic slots derived from agent ID. Event stimuli (damage, loud sound, goal invalidation) may wake an agent immediately. Use spatial broadphase before LOS, bound raycasts and path searches per host tick, cache corridor until meaningful invalidation, reuse squad-wide information, and sleep distant agents according to gameplay rules. Visibility to a local camera alone is unsafe for throttling a host: remote players may still interact with the NPC. Agent LOD should depend on relevance to *all* players and active world events.

Use fixed work budgets with deferred queues and measurable counters: agents awake, sensor checks, LOS casts, nav queries, expanded polygons, decision evaluations, average and worst tick milliseconds, memory, and bytes per agent per second. Preserve deterministic queue ordering for reproducible host traces, while accepting that clients are snapshot-driven. Profile low-end Android as host with 1, 8, 16 and 32 agents in an original synthetic world before selecting caps or update intervals. Set a fallback behavior when budgets are exceeded; silent skipped correctness checks are unacceptable.
