# Utility decisions

**VERIFIED local example:** Natural Selection 2's installed `ns2/lua/bots/PlayerBrain.lua` evaluates immediate action weights, validates a current objective, and updates objectives at a slower rate (`kObjectiveUpdateRate = 1` in the inspected version). Its debug manager records action and goal names/weights. This is a useful hybrid precedent, not proof that its weights transfer to MegaMod. Dave Mark and Kevin Dill's [utility modeling talk](https://www.gamedeveloper.com/business/video-embracing-the-dark-art-of-mathematical-modeling-in-ai) describes reusable considerations and mathematical response curves.

A utility candidate computes a score from normalized considerations: distance, health, ammo, threat, goal urgency, cover availability. Define every input's unit and `[0,1]` mapping, curve, missing-data behavior and combination rule. A weighted sum allows compensation; a product can collapse to zero. Either can be correct for a specific choice. Clamp and record intermediate values. Use an inertia bonus, minimum dwell or switch threshold so tiny score changes do not flip goals each think tick. Urgent events may bypass the dwell. Keep objective selection slower than steering and reactive combat checks.

**Good use:** choosing between patrol, investigate, chase, retreat or heal when tradeoffs are continuous. **Poor use:** expressing a multi-step dependency like “open door before entering room” solely as scores. That requires action state, a short authored sequence, or a planner. Utility scoring can choose *which goal*, while a small task executor runs it. Action failure feeds back by temporarily penalizing or invalidating the candidate.

**Recommendation:** use simple documented scores only after a rule-based first agent exposes the necessary sensor data. Ship score breakdown and selected/runner-up values in host debugging from day one of utility adoption. Treat NS2's numeric update interval as game-specific, not a MegaMod target.
