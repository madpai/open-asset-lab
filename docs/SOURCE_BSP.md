# Source BSP v20 importer

Authoritative layout reference: [Valve Source SDK 2013 `bspfile.h`](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/public/bspfile.h) and [surface flags](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/public/bspflags.h). We evaluated [BSPSource](https://github.com/ata4/bspsrc) (Java decompiler, BSD 3-Clause, broader than needed), [bsp_tool](https://github.com/snake-biscuits/bsp_tool) (Python, GPL, useful tests and many formats), and [vbsp](https://github.com/icewind1991/vbsp) (Rust, MIT, test map). A small bounded Python reader was chosen to avoid embedding a large converter and to produce the exact Open Halo contract. No third-party parser code was copied.

Supported: little-endian `VBSP` version 20, face lump version 1, Source LZMA compressed lumps, vertices/planes/edges/surfedges/faces/models, texinfo/texdata/material string table, displacement info/verts powers 2–4, entities, static-prop game lump v10 inventory, and BSP embedded pakfile. Each lump offset, compressed size, array stride, face edge and vertex index is checked before use. The 512 MiB source cap limits allocations. Unknown BSP versions and face layouts fail.

Source and Open Halo are right-handed, +Z-up XYZ. One Source unit is treated as one inch; one Open Halo world unit is ten feet, so the transform is `runtime = source / 120`. No axis reflection occurs. Source face surfedge order is checked against its plane normal and `side` flag; triangles are flipped to match the intended outward normal. UVs use texinfo texture vectors and texdata dimensions. Displacement base quads are oriented from `startPosition`, bilinearly interpolated, displaced with each vertex vector times distance and split into two triangles per cell. Invisible sky, trigger, nodraw, hint and skip surfaces are excluded. Visible world faces, including displacements, form a conservative collision mesh. There is no clip-brush import.

VMT lookup checks the embedded pakfile first, then explicit unpacked roots, then explicitly configured `_dir.vpk` archives using srctools. VPKs require their numbered data archives alongside the directory file. Supported albedo VTF formats: RGBA8888, BGRA8888, DXT1 and DXT5 with bounded dimensions. Unsupported Source shaders or absent materials use a muted material-specific placeholder, with exact missing paths and placeholder names in the manifest. Transparency, shader patch inheritance, blend maps, bump maps, cubemaps and lightmaps are not yet reproduced. Static props are counted and model paths reported, not rendered. Entity classes are inventoried; `info_player_start`, `info_player_deathmatch`, `info_player_teamspawn` and common CS player spawns are extracted. Entity scripts are never executed.

The chosen real map `koth_bagel_rc2a.bsp` is Source v20 with compressed lumps, 757 displacement records, 1,211 static props and an embedded pakfile. It needs TF2 base content for most materials and props, so this conversion proves world geometry and host rendering, not a complete visual/behavioral TF2 level. A smaller handmade Source test map from [bsp_tool's test maps](https://github.com/snake-biscuits/bsp_tool/tree/master/tests/maps/Team%20Fortress%202) checks another v20 file and three displacement surfaces. Both are kept private outside the public repository.
